================================================================
  校园网自动登录脚本 —— 使用说明
================================================================

【这是什么】

一个自动登录校园网的小工具。开机后、或者校园网掉线后，它会自己
帮你填学号密码、认验证码、点登录。

原理是用浏览器自动化（Selenium 驱动 Chrome/Edge），不是破解协议。
每隔几分钟就检查一次网络状态：有网就什么都不做，没网才动手。


【运行前需要什么】

1. Windows 系统
2. Python 3.10 或更高版本
   没装的话去 https://www.python.org/downloads/ 下载
   ★ 安装时务必勾选 "Add Python to PATH"
3. Chrome 或 Edge 浏览器（Windows 一般自带 Edge）


【安装步骤】

第 1 步  解压
    右键这个 zip → 全部解压缩，解到任意位置。

第 2 步  装依赖
    进入解压出来的 campus-net 文件夹，在文件夹窗口的「地址栏」
    输入 cmd 回车（会在该目录打开命令行），然后执行：

        pip install -r requirements.txt

    会联网下载 selenium、ddddocr 等几个包，等它跑完。

第 3 步  配置
    在同一个窗口里执行：

        copy config.example.json config.json
        notepad config.json

    记事本打开后，把这一行的学号改成你自己的：

        "username": "你的学号",

    如果用的是 Edge 而不是 Chrome，把

        "browser": "chrome",

    改成

        "browser": "edge",

    保存并关闭记事本。

第 4 步  存密码
    执行：

        python login.py --setup

    - 提示「学号/账号 [xxx]:」→ 直接回车
    - 提示「密码（输入时不显示）:」→ 输入密码
      ★ 屏幕上不会有任何字符显示，这是正常的，输完回车
    - 显示「密码已加密保存到 ...」就成功了

    密码用 Windows 自带的加密（DPAPI）保存，绑定你这台电脑的这个
    账户。别人拿到文件也解不开，也不会写进任何配置文件。

第 5 步  测试
    先断开校园网（注销，或等它自己掉线），然后双击：

        test-login.bat

    会弹出浏览器自动填表登录，整个过程 20-40 秒。
    窗口最后会显示结果。

第 6 步  设置开机自动运行
    执行：

        powershell -ExecutionPolicy Bypass -File install_task.ps1

    显示「已注册计划任务」就成功了。之后它会：

        - 你每次登录 Windows 时自动检查一次
        - 每隔 5 分钟检查一次
        - 有网：什么都不做，不弹窗、不打扰
        - 没网：自动启动浏览器登录


【日常使用】

装好之后基本不用管。

  想看它干了什么 ...... 打开 campus-net.log，最近的记录在最下面
  想手动跑一次 ........ 双击 test-login.bat
  想手动更新驱动 ...... python login.py --update-driver
  想卸载 .............. powershell -ExecutionPolicy Bypass -File uninstall_task.ps1


【关于安全，你需要知道】

1. 脚本会替你在登录页上勾选「已阅读并同意《用户协议》《免责声明
   协议》《用户隐私协议》」。因为不勾的话登录按钮不生效。
   也就是说：这几个法律条款是由程序代表你接受的。

2. 你的密码不会出现在任何配置文件里，加密存在 secret.dat。

3. 如果 6 小时内连续失败 6 次，脚本会自己停下来不再尝试。这是为了
   防止你的账号被学校认证系统锁掉。手动登录成功一次后会自动恢复。

4. 每次尝试都会真的向学校服务器提交一次登录请求。所以改了密码
   记得重新跑一次第 4 步。


【出问题了怎么办】

问题：双击 test-login.bat，窗口里是乱码
    → 说明这个文件被记事本之类的编辑器保存过，编码坏了。
      重新解压一份即可。切记不要用记事本编辑 .bat 文件。

问题：浏览器弹出来，闪一下就没了
    → 这是失败的表现。看目录里的 failure-*.png（失败瞬间的屏幕
      截图）和 failure-*.html，以及 campus-net.log，基本能看出
      卡在哪一步。

问题：日志里说「等待页面稳定超时」或「页面加载超时」
    → 学校登录页加载太慢。这两个等待上限是写死在 src/browser_login.py 里的
      常量（_SETTLE_TIMEOUT 和 _PAGE_LOAD_TIMEOUT，都是 20 秒），
      config.json 里的 probe_timeout 管不到它们 —— 那一项只影响 HTTP 探测
      请求。（2026-10-15 之前 _PAGE_LOAD_TIMEOUT 误用了 probe_timeout 的
      5 秒，开机时认证页还没加载出来就放弃，所以才有这条提示的由来。）

问题：找不到登录页上的输入框
    → 说明页面结构和预期不同。执行：

          python login.py --dump-form

      它会把页面上所有输入框、图片、按钮列出来。
      照着结果修改 config.json 里的 selectors。

问题：日志里说「This version of ChromeDriver only supports Chrome version 154」
    → 浏览器自己升级了，本地缓存的驱动是旧版本。这条现在基本能自愈：
      脚本每一轮「已在线」的检查都会顺手比对一次，不一致就自动下载对应
      版本、校验后装进缓存（优先国内镜像，官方源兜底，通常几秒钟）。
      2026-10-23 那次坏了一整天，就是因为当时没有这一步：能下载的时候
      脚本已在线、根本不启动浏览器，真要登录时又没网，永远补不上。
      想立刻补，手动跑：

          python login.py --update-driver

      日志里会出现「驱动已匹配：Chrome 157.0.8103.80，缓存中 …」或者
      「驱动已自动更新：…」。失败后 6 小时内不再自动重试（免得每轮都挂
      超时）；想强制再试，把上面那条命令再跑一次 —— 手动命令忽略冷却。

问题：唤醒后日志里说「页面停在 Chrome 的网络错误页（ERR_NETWORK_CHANGED）」
    → 这不是故障，是刚结束睡眠时网卡还在反复重连。2026-10-28 21:00 实测：
      网卡在唤醒后 15 秒内切了 6 次状态，浏览器正好在这段时间打开页面，
      Chrome 直接报「您的连接已中断 / 检测到了网络变化」，而且会一直停在
      那张错误页上（它不会自己重载）。
      现在脚本会认出这类错误页并自动重新加载（最多 3 次、每次隔 6 秒），
      网络一稳就能接着登录；如果 18 秒后还是错误页，那一轮按
      network_unstable 收尾 —— 一个凭据都没提交，所以不记失败、不退避，
      5 分钟后的下一轮会自然再试。

问题：我不是四川工业科技学院的学生
    → config.json 里的 selectors 是针对该校门户量出来的，别的学校
      需要重新量（用上面的 --dump-form）。
      另外 portal 那一项也要改成自己学校的门户地址。

问题：账号被锁了
    → 先卸载计划任务（见上面「想卸载」），联系学校网管解锁，
      然后检查 config.json 里的学号是否正确、密码是否输错。


【技术细节（可选阅读）】

  语言        Python 3
  浏览器自动化 Selenium（Chrome / Edge）
  验证码识别   ddddocr，本地识别，不联网、不调用任何外部服务
  密码存储     Windows DPAPI（ctypes 直接调用，无第三方依赖）
  触发方式     Windows 计划任务（登录时 + 每 5 分钟 + 网络状态变化时）
               摸不到门户时会再探几次（默认 12 次、每次隔 5 秒，可改
               config.json 的 portal_wait_probes）—— 开机后刚连上 WiFi、
               门户还没就绪的那几十秒不会再像以前那样被白白浪费
               打开认证页失败（没提交任何凭据）不计入失败计数、也不退避，
               所以那一次失败不会把接下来 15 分钟的重试挡掉
               唤醒后撞上 Chrome 的网络错误页会自己重新加载（3 次 × 6 秒），
               仍然不行就按 network_unstable 收尾，同样不记失败、不退避
               登录失败后会退避（默认 15 分钟不再重试），
               所以轮询虽快，登录尝试的密度仍被限住，不会把账号试锁
               不是常驻进程 —— 每次跑几秒就退出（摸不到门户那种最多约
               60 秒），崩了下一轮自动重来
  探测逻辑     请求外部地址判断外网是否通，被劫持才判定需要登录
  驱动版本     优先选与 Chrome 主版本一致的 chromedriver；差一个主版本时
               先拿现有的试（实测通常能用），起不来再让 Selenium Manager
               联网解析。已经在线时自动补齐匹配版本（优先国内镜像，官方源
               兜底，实测 4 秒下完 11 MB），失败后 6 小时内不重试
  安全设计     重试上限 + 跨运行失败计数，避免把账号试错锁

本工具仅供个人在自己的账号、自己的设备上使用。
